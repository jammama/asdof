# asdof-random — 제비뽑기

참가 절차 없음. 링크를 연 사람은 누구나 같은 명단·같은 결과를 본다.
**명단과 항목(인원)은 뽑기 전이면 화면에서 바로 고칠 수 있다.**
`asdof-chat`(anonchat)의 허브/방 구조를 베이스로 만든 독립 서비스.

- 서빙: <https://random.asdof.xyz/> — **루트는 방 만들기 화면**(방 이름 입력, 기본값 `랜덤 팀뽑기`).
  이름을 정하면 무작위 10글자 키를 만들어 `/<키>` 로 이동한다. **경로가 곧 판의 키**이고, 방 이름은 표시용 라벨일 뿐이다.
  키를 아는 사람은 `/<키>` 로 바로 들어오면 되고, 헤더의 방 이름을 눌러 언제든 이름을 바꿀 수 있다
- 명단: 판을 처음 열 때는 서버 파일(`/var/lib/asdof-random/members.md` ← 로컬 `.knowledge/members.md`, deploy.sh 가 올림)에서 읽고,
  그 뒤엔 화면의 「명단 수정」에서 바꿀 수 있다(「기본값 되돌리기」= 명단·항목 모두 서버 기본값으로)
- **결과는 서버에 저장**(`draws.json`) → 아무도 보고 있지 않아도, 서버를 재시작해도 남는다

## 뽑기 방식

항목마다 **인원(자리)** 이 있고, 자리를 인원만큼 제비로 만들어 섞은 뒤 명단에 나눠준다.
기본값은 자리 표시용(멤버 `참석자1~5`, 항목 `항목1 3인` / `항목2 2인` — 자리 합 5 = 명단 5명)이고,
실제 명단·항목은 화면에서 채워 넣는다. 「기본값 되돌리기」로 언제든 이 상태로 복귀.

- 자리 > 멤버 → 남는 자리는 무작위로 빠짐
- 자리 < 멤버 → 모자란 만큼 꽝
- 섞기는 `crypto/rand` 시드 → 순서에 따른 유불리 없음(확률 = 자리수/인원)

항목 입력은 한 줄에 하나, 줄 끝의 `3인`/`x3`/`(3)` 을 인원으로 읽는다(없으면 1명).
그래서 받은 목록을 그대로 붙여넣으면 된다:

```
프랭크의 골동품가게 : Plan to save my dear [공포] 3인
무비무드 : 5관 E열 4번 [감성] 3인
...
```

## 흐름

1. 링크 공유 → 아무나 **명단·항목을 수정**하고 **제비 뽑기**(확인 모달)
2. 제비가 순서대로 뒤집히며 공개 → 항목별 배정 명단
3. 결과는 저장됨 — 나중에 들어온 사람은 애니메이션 없이 바로 결과를 본다
4. **다시 뽑기**(확인 모달)를 누르면 결과가 지워지고 새로 뽑는다

- 뽑은 뒤에는 명단·항목 변경과 재뽑기가 막힌다(결과 보존). 바꾸려면 「다시 뽑기」 먼저.
- 이름을 붙였거나 명단/항목을 고쳤거나 결과가 있는 판은 저장되어 아무도 없어도 유지된다(다음에 열면 그대로).
  뽑지 않은 채 30일 지난 판은 서버 시작 시 정리된다.
- 화면에서 **자기 이름을 누르면 「나」로 표시**되어 내 결과가 위 배너에 뜬다(브라우저에만 저장, 서버로 안 감).
- 명단 최대 60명 · 항목 최대 12개 · 항목당 최대 60인.

## 구성

| 파일 | 설명 |
|---|---|
| `main.go` | 명단 로드 / 판·뽑기 / 결과 저장 + WebSocket + 정적 서빙 (단일 바이너리) |
| `main_test.go` | 자리 배분(정확/부족/초과), 확률 균등, 명단 파싱, 재시작 후 결과 복원 |
| `static/index.html` | 화면 전체(제비 카드 뒤집기). 외부 의존성 0 |
| `asdof-random.service` | systemd 유닛 (`127.0.0.1:8770`, www-data, MemoryMax=128M) |
| `nginx-random.conf` | nginx vhost (프록시 + WebSocket 업그레이드) |
| `deploy.sh` | 크로스빌드 → 설치 → 기동 (`--nginx` 로 vhost+TLS) |

## 프로토콜

WebSocket `/_ws?room=<판>` — JSON 텍스트. (식별자 없음 — 접속자 모두 같은 상태를 받는다)

클라이언트 → 서버: `title{title}` · `config{members?:[…], pool?:[{name,seats}]}` · `reload`(명단·항목 기본값 복귀) · `draw` · `reset`
(권한 구분 없음 — 링크를 가진 사람끼리 쓰는 도구)

서버 → 클라이언트: `state` 하나로 판 전체를 보낸다 —
`room`(키) · `title`(방 이름) · `members[]` · `pool[]` · `viewers` · `round` · `custom`(화면에서 고친 판인지) · 뽑은 뒤 `draw[]`(멤버별 항목 인덱스, -1 은 꽝) ·
`drawnAt`(뽑은 시각) · `elapsed`(서버 기준 경과 ms → 늦게 들어오면 애니메이션 건너뜀). 안내는 `notice`.

## 로컬 실행 / 배포

```bash
MEMBERS_FILE=../.knowledge/members.md go run .   # http://localhost:8770
./deploy.sh                    # 앱 + 명단 갱신
./deploy.sh --nginx            # 최초 1회: vhost + Let's Encrypt
```

`.knowledge/members.md` 를 바꿨으면 `./deploy.sh` 로 올려야 **기본 명단**에 반영된다(시작 시 1회 로드).
급하면 화면의 「명단 수정」으로 그 판만 바꿔도 된다.

지난 뽑기 결과 사본은 `.knowledge/draw-results.md`, 실제 멤버 명단 원본은 `.knowledge/members-real.md` 에 보관해 뒀다
(`members.md` 는 자리 표시용 기본값으로 교체됨).

앱은 `127.0.0.1:8770` 에만 바인딩하고 nginx 가 앞단에서 프록시한다. 서버 정보는 `../.knowledge/spec.md`.
